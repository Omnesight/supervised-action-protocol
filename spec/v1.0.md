# Supervised Action Protocol (SAP) Specification — v1.0.0

## 1. Purpose & Scope
The **Supervised Action Protocol (SAP)** establishes a deterministic, zero-trust governance boundary between autonomous cognitive/scientific AI engines (including **Hackmalim v1.0** and **Sandalfon v1.0**) and mission-critical systems of record (ERP ledgers, power grids, SCADA valves).

Every proposed action must pass **four sequential invariants** before reaching `COMMITTED`.

---

## 2. State Machine
| State | Meaning | Transition Condition |
| :--- | :--- | :--- |
| `PROPOSED` | Action emitted by an AI engine | Payload conforms to `schemas/action.schema.json` |
| `VALIDATING` | Deterministic guardrail & SAT check | Verifies grounding, confidence, financial cap, and physical axioms |
| `SUPERVISED_APPROVAL_MANDATED` | Escalated to human supervisor | Triggered if confidence `< 0.92`, financial impact `> $10,000`, or an axiom fails |
| `APPROVED` | Signed by human supervisor | Dual-key or supervisor identity attested |
| `COMMITTED` | Applied on target system | Produces canonical `sha256_audit_hash` |
| `REVERTED` | Compensating rollback executed | Triggered by post-commit anomaly or manual revert |

---

## 3. Core Safety Invariants

### 3.1 Entity Grounding (Zero-Hallucination Check)
`target_entity_id` **must** appear verbatim in the signed telemetry payload or verified asset registry (`source_telemetry`). Phantom identifiers are rejected immediately.

### 3.2 Confidence & Financial Boundaries
- **Confidence Threshold:** Actions with `confidence_score < 0.92` cannot auto-commit and escalate to `SUPERVISED_APPROVAL_MANDATED`.
- **Autonomous Financial Limit:** Actions with `financial_impact_usd > 10000.0` require human sign-off regardless of confidence.

### 3.3 Neuro-Symbolic SAT Axiom Verification
For physical infrastructure actuation (`GRID_THERMAL_CONTAINMENT`, `PIPELINE_VALVE_ACTUATION`, `CUSTOM_SCADA`, `OMNESIGHT_SOVEREIGN_GRID`), actions must satisfy hard safety axioms:
1. **Power Ceiling Axiom:** $P \le P_{\max}$ (`power_kw <= max_power_kw`)
2. **Thermal Ceiling Axiom:** $T \le T_{\max}$ (`temp_c <= t_max_c`)
3. **Mutex Interlock Axiom:** $\neg(\text{AuxBypass} \wedge \text{LoadShed})$ (`not (aux_bypass == 1 and load_shed == 1)`)

Any tuple violating an axiom is marked `UNSAT`, rejected before actuation, and recorded with its violation trace.

---

## 4. Cryptographic Provenance (`sha256_audit_hash`)
Every validation produces a deterministic SHA-256 digest over canonicalized JSON (`sort_keys=True`) binding:
- `action_id`, `action_type`, `target_system`, `target_entity_id`
- `financial_impact_usd`, `confidence_score`
- `axioms_checked`, `sat_verified`, `source_telemetry_sha256`
